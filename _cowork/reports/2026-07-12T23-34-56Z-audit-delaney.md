# [Delaney] Codebase audit — delaney — 2026-07-12

> Read-only prose audit of the delaney (KidBlock) repo, Phase A of the `audit-and-refresh-arch` composite. Four sources walked: the kernel-side `_cowork/dashboard-delaney.json`; the MOUNT working-agreement (absent — kernel canonical governs per `AGENTS.md`); the MOUNT `_cowork/runs/` history (DM1–DM11 run-logs + the 2026-06-10 prior audit-and-refresh-arch log); and the source tree under `C:\CC\delaney` (excluding `bin/`, `obj/`, `.git/`). KidBlock is an early-but-shipping project (DM1–DM23 landed, DM24 docs on top); the findings list is deliberately short. Every finding cites a path and a one-line evidence note; domains with nothing real to report say so.

## Findings

### 1. Dead / orphaned code

(no findings) — every model / service / view-model / converter symbol resolves to at least one live reference (`DiffLine`, `AllowDurations`, `DomainCategorizer`, `InvertBoolConverter`, `CategoryViewModel`, `DomainCheckboxViewModel` all have non-defining references in `windows-ui/KidBlockUI/`), and a tree-wide scan found no `TODO` / `FIXME` / `HACK` / `NotImplemented` markers (the sole `XXXXXX` hit is a `mktemp` template in `Services/RouterClient.cs:134`). Nothing orphaned to flag.

### 2. Logging-strategy consistency

- `windows-ui/KidBlockUI/App.xaml.cs` (lines 71, 153, 216, 221, 225): app-side diagnostics for tray-init failure, tray-icon extraction failure, and Syncfusion licence-registration outcome all go through `System.Diagnostics.Debug.WriteLine`. `Debug.WriteLine` is `[Conditional("DEBUG")]`, so in a Release build these calls are compiled out entirely — a shipped, long-running minimise-to-tray app has no persistent app-side trace of a licence or tray failure. This is inconsistent with the router half of the system, which writes a durable `log()` append to `/var/log/kidblock.log` (`router/kidblock.sh`) that the UI itself tails. User-facing operation errors are surfaced coherently (ViewModels → `MessageBox` / status text; `ViewModels/MainViewModel.cs` carries the catch/surface pattern), so the gap is narrowly the developer-diagnostic channel, not error reporting. Minor for an early project.

### 3. Architectural drift from the stated north-star

(no findings) — the README/arch north-star is "scheduled internet control for an EdgeRouter Pro 8, enforced on-device so blocking survives the notebook sleeping." The two front-ends (`windows/*.ps1` + `windows-ui/KidBlockUI/`) both drive the same router-side `router/kidblock.sh` over SSH, and enforcement lives entirely on the router (iptables/dnsmasq/ipset + a 1-minute task-scheduler tick + `router/kidblock-init.sh` boot hook). Every boundary node in the arch snapshot traces to a real file; no aspirational or drifted structure was found.

### 4. UX inconsistencies

(no findings within this pass) — the override-minute ceiling is enforced consistently across surfaces (`Services/RouterClient.cs:238-240,259-261` caps at 1–1440 "to match the PS1 shortcuts"), and both front-ends are documented as interchangeable and stateless (`README.md` control-surfaces table). No cross-surface behavioural contradiction surfaced from the service/app-shell read; a deep per-view interaction pass was out of scope for this audit and is not asserted either way.

### 5. Dependency-view confusion in the dashboard

- `_cowork/dashboard-delaney.json`: `current_focus` still literally reads *"Project bootstrap -- no milestones yet. Owner pins the first work via INGEST-IDEA…"* and all four WBS phases (`P1`–`P4`) carry `children: []`, yet the same file's `_migration_history` records **23 milestones graduated** (DM1–DM23, 2026-06-03 → 06-25) shipping a full KidBlockUI + Syncfusion Ribbon program. The dependency graph the dashboard renders is therefore an empty bootstrap surface while the project has demonstrably shipped — the `current_focus` line is stale and no next-work node is seeded. (Graduated rows correctly leave the WBS for `_cowork/milestones-done/`; the confusion is the un-updated `current_focus` string + the absence of any live/proposed node, not the empty WBS itself.)
- `_cowork/dashboard-delaney.json` + repo history: DM24 shipped as a plain `docs:` commit (`655c0ac`) with **no** `graduate-milestone` entry in `_migration_history` and **no** run-log under `_cowork/runs/` (contrast DM1–DM11, each with a run-log). Minor milestone-bookkeeping gap; noted for completeness.
